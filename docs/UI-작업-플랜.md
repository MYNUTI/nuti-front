#### 이 브랜치의 남은 질문

- **5-1 알림 띠 너비** — 【최종】의 알림 줄 알림 띠 2개(로그인 전 · 후)는 좌우 꽉 찬 362인데, 공통 `Toast`는 글 길이만큼 줄어든다. 지금은 글 길이대로 둔다. 디자이너 확인
- **5-1 알림 「누른 수만 기록함」** — 메모는 알림 줄을 누른 수를 기록한다(로그인 전은 기기 익명 ID)고 하는데 보낼 곳(API · 분석 이벤트)이 없다. 백엔드 · 기획 확인
- **5-1 로그인 권하는 알림 띠가 떠 있는 시간** — 메모 「안 정함: 글만 있는 띠보다 길게」. 지금은 같은 3초(버튼에 손가락 · 마우스가 닿아 있는 동안은 멈춤). 디자이너 확인
- **5-2 근육 증가 카드 설명** — 【최종】 5-2는 「단백질이 충분하면 / 칼로리가 높을수록 좋아요」, 1-5는 「단백질이 충분하면 / 100g당 칼로리가 높을수록 / 점수가 높아요」로 다르다. 화면마다 【최종】대로 뒀다. 같은 문장이어야 하는지 디자이너 확인
- **5-2 키보드로 고를 때** — 메모대로 카드를 고르는 즉시 바뀐다. 라디오 묶음이라 키보드 화살표로 옮겨도 바로 바뀌고 5-1로 넘어간다(5-1의 「되돌리기」로 되돌릴 수 있음). 디자이너 확인
- **5-6a 「Notice warn」 모양** — ⑩ 상태표는 실패 문장을 「버튼 위 Notice warn」으로 두는데 디자인 시스템(【최종】 · 원래 판)에 warn 모양이 없다. 지금은 기본 `Notice`(회색 바탕 + i 아이콘). 디자이너 확인
- **5-6a 앱 안 브라우저에서 구글** — 메모는 문장 「이 앱 안에서는 구글 로그인이 열리지 않을 수 있어요」와 「다른 브라우저로 열기」만 있고 모양이 없다. 지금은 실패 안내와 같은 자리의 `Notice` + 글자 버튼(바깥으로 열 방법이 없는 곳은 버튼 뺌). 디자이너 확인. 실기기(카카오톡) 확인도 남음
- **5-6a 「마이뉴티」 글꼴** — 【최종】은 「학교안심 알림장」. 글꼴을 넣을지(라이선스 · 용량), 글자 이미지로 둘지, Pretendard로 둘지 디자이너 확인
- **5-6 필수 문장 · 가입 실패 문장 자리** — 둘 다 디자인 그림이 없다. 지금은 필수 문장은 필수 줄 아래, 실패 문장은 「동의하고 시작하기」 바로 위. 디자이너 확인
- **5-6 목표 없는 사람의 목표 저장 시트** — 목표 줄은 메모대로 「고른 목표를 계정에 저장」인데, 시트의 「항목」 줄(「고른 목표: 다이어트(민감정보)」)은 목표가 없을 때의 문장이 없다. 지금은 「고른 목표(민감정보)」. 디자이너 확인
- **5-6c 「목표를 골라 주세요.」 모양** — 메모는 「카드 위에」 · 「그림 없음」뿐이다. 지금은 제목과 카드 사이에 빨간 Body2. 디자이너 확인
- **5-6c 광고성 정보 알림 다시 뜸** — 5-6b에서 뒤로 돌아오면 알림이 한 번 더 뜬다(주소 `?ads=1`이 남아서). 가입 API를 붙이면 동의 결과를 서버 응답으로 받아 한 번만 띄운다
- **5-6b 기록 옮기기 실패 문장 자리** — 메모는 문장만 있다. 지금은 제목 아래 설명 줄(「이 기기의 기록을 계정으로 옮겼어요.」 자리)을 이 문장으로 바꾸고 「옮긴 기록」 줄을 숨긴다. 디자이너 확인
- **5-6b 이메일 가림 규칙** — 메모는 「일부를 가림」뿐이다(그림 「ab***@kakao.com」). 서버가 가려 주는지, 화면이 앞 두 글자만 남기는지 백엔드 · 디자이너 확인

- **5-5 계정 삭제 「남는 것」 문장(안 정함)** — 변호사 확인(ACCT_008). 디자인대로 만들었다

## 작업 방식

화면 하나(위 표의 한 줄)마다 아래 순서로 하고, 끝나면 확인받는다.

1. 기본 프레임과 상태 프레임 전부, 메모, 상태표 줄을 읽는다
2. 화면에 필요한 데이터를 **화면 props 타입**으로 정한다. API 타입(`lib/<도메인>/types.ts`)은 API 브랜치 몫이라 여기서 만들지 않는다
3. 공통 부품을 우선 쓰고, 없는 부품은 00단계 부품에 추가할지 화면 전용으로 둘지 정한다
4. 상태 프레임을 모두 재현한다. 서버 응답이 필요한 상태는 임시 데이터로 고정해서 확인한다(아래 「데이터」)
5. 메모의 「누르면」 이동을 연결한다. 아직 없는 화면으로 가는 링크는 경로만 걸어 둔다
6. `pnpm typecheck`, `pnpm lint`, `pnpm test` 통과 → 개발 서버에서 피그마 스크린샷과 비교 → 확인 요청

### 데이터

API 연결은 API 브랜치 08·09단계 이후에 붙인다. 그 전까지 화면은 props로만 데이터를 받는다.

- 임시 데이터는 화면 폴더 옆(`src/app/<경로>/_fixtures.ts`)에 둔다. `src/lib/`에 두지 않는다
- 나중에 연결할 때는 fixture import를 쿼리 훅 + mapper로 바꾸는 것만 남도록, 화면 props는 서버 필드 이름이 아니라 화면이 쓰는 모양으로 정한다
- 담기·즐겨찾기·지우기처럼 서버 변경이 필요한 동작은 지금은 화면 안 상태로만 처리한다(예외: 비교함은 서버 API가 없어 브라우저 저장소에 둔다 — 2026-11-21 결정)

27. **2-3 검색어 길이** — `GET /search/suggestions`는 30자를 넘으면 400이다. 입력을 30자에서 막을지, 넘으면 자동완성만 쉬고 검색은 할지 디자인에 없다. 지금은 막지 않는다(API 연결 때 넘는 글자는 자동완성을 부르지 않게 한다). 디자이너 확인
28. **2-4 검색 결과와 API** — 화면은 정렬 4종(점수 · 칼로리 · 단백질 · 당류), 0~100 점수 · 구간, 「○○ 순위 보기」의 대표 분류를 쓰는데 `GET /search`(`SearchDto`)에는 정렬 파라미터 · 점수(등급 글자만) · 분류가 없다. 결과는 같은 검색어 · 정렬을 주소(`&sort=` · `&n=`)로 되살린다. 백엔드 확인
