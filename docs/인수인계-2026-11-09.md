## 꼭 알아야 할 주의점

1. **개발 서버가 없다. 개발 중에도 배포 서버(운영 데이터)를 부른다.** 팀이 허용한 부수 효과지만 최소화한다
   - 상품 조회만 해도 조회수가 오르고(인기·추천 정렬에 반영), 없는 바코드는 분석 대기 목록에 등록된다
   - 변경 API·로그인도 운영 데이터에 남는다. 실험 삼아 반복 호출하지 않는다
2. **`src/lib/`은 API 작업, `src/app`·`src/components`는 UI 작업 영역**이다. UI 작업 중 `src/lib/`은 import만 한다(예외: `lib/pwa.ts`의 `SPLASH_COLOR`, `lib/utils.ts`의 `cn`). API 작업(06단계 스캔·상세 연결, `/grades/guide` 데이터 레이어)을 같이 할 때는 해당 `src/lib/` 파일과 테스트를 고친다(목 `lookupProduct`는 `lib/scan/lookup.ts`·`lookup.test.ts`, `ScanResult`는 `lib/scan/types.ts`)
3. 현재 `src/app` 라우트 중 v3 디자인으로 다시 만든 것은 `/`, `/intro`, `/intro/2`, `/intro/goal`, `/home`, `/scan`의 0-3·0-3x·3-1(기본과 상태 6개, 아래 「UI 현황」)뿐이다. 3-1의 조회 결과 시트·카메라 점유 띠와 나머지(`scan`, `history`, `settings`, `product/[id]`, `onboarding/*`)는 **임시본이라 기준으로 삼지 않는다**. `scan`·`product/[id]`·`history`·`settings`는 해당 단계에서 같은 경로로 다시 만들고, 대체된 `onboarding/*`는 13단계에서 지운다
4. 상품 상세(`/product/[id]`)와 스캔 조회(`src/lib/scan/lookup.ts`의 `lookupProduct`)는 아직 목 카탈로그(`src/lib/mock-catalog.ts`)를 쓴다. 홈은 `src/app/home/_fixtures.ts`를 쓰고, 「최근 본 제품」은 맞는 1차 API가 없어 연결하지 않는다
5. 피그마·명세에 없거나 「안 정함」인 부분은 추측해서 채우지 않는다. 플랜 문서의 「남은 질문」에 적고 넘어간다

## 브랜치·커밋

- `main`에 PR로 머지한다. 지금까지는 `feat/api`, `feat/ui`에서 머지했다(PR #2, #3)

### 남은 것

1. **06단계 화면 연결 — 스캔·상세** (UI 03·04단계와 같이 하는 게 맞다)
   - `src/components/scan/scan-stage.tsx`를 `lookupProduct`(목) → `useProductByBarcode`로 바꾸고 등급 없음(`INSUFFICIENT`)·미등록(404)·체크섬 오류 분기를 넣는다. 3-1 숫자로 입력 시트(`scan-manual-sheet.tsx`)는 디자인 메모대로 체크섬이 틀리면 조회하지 않고 오류만 보인다. `lib/scan/gtin.ts`의 `checkGtinInput` 설명(「empty만 제출을 막는다」)과 다르니 이때 맞춘다. 앞자리가 0이 아닌 14자리 직접 입력(400)을 입력 단계에서 막을지 정한다. 목 `lookupProduct`·`ScanResult`는 지운다
   - `src/app/product/[id]/page.tsx`를 `getProductDetail` + `notFound()` + `HydrationBoundary`로 바꾼다. **서버 prefetch용 QueryClient는 `retry`를 끈다**(안 끄면 조회수가 두 번 오를 수 있다)
   - 실제 서버로 확인: `cache()` 중복 제거, 스캔 → 상세 이동, proxy 갱신 뒤 개인 기준 등급 렌더
2. **나머지 화면 연결** — 각 화면의 `_fixtures.ts` import를 쿼리 훅 + mapper로 바꾼다. 맞는 1차 API가 없는 값(홈 「최근 본 제품」, 2차 범위인 등급 순위 등)은 fixture로 둔다. 화면 연결 때 챙길 것(버튼 `isPending` 잠금, 동의 게이트 감싸는 법, 검색 디바운스·30자 제한 등)은 API 플랜 「화면 연결 때 챙길 것」에 정리돼 있다. **연결 전에 꼭 읽을 것**
3. **11단계 OAuth 콜백 화면** — 아래 「막힌 질문」 1~3번 답이 와야 시작할 수 있다
4. 토스트·세션 만료 알림 UI — 데이터 쪽은 `setMutationErrorListener`, `onSessionExpired`까지 있고 화면이 등록만 하면 된다. 알림 띠 부품은 `components/common/toast.tsx`(`Toast`)에 있다
5. **`GET /grades/guide` 데이터 레이어** — 5-4 「등급은 어떻게 매기나」(UI 04단계)가 쓴다. 아직 API 함수·훅이 없어 `src/lib/product/`에 다른 도메인과 같은 구조로 만든다. API 플랜 매핑표는 식별을 「없음」으로 적었지만 백엔드(`GradeController`)는 식별을 받아 `goal`을 생략하면 내 목표(없으면 GENERAL)로 답한다. 식별을 붙일지, `goal`을 항상 보낼지 만들 때 정한다

    - 「시트를 아래로 밀면 닫힘」은 공통 `BottomSheet`가 맡는다. 손잡이·제목 줄을 80px 넘게 내리거나 빠르게 내리면 닫힌다(내용 칸은 스크롤·버튼과 섞이지 않게 끌기를 받지 않는다)
    - 「영양성분표 찍고 점수 보기」는 `/contribute/label`(3-7, 아직 없는 경로)
  - 3-1 카메라를 못 여는 곳(`src/components/scan/camera-place.ts`·`no-camera-sheet.tsx`): `/scan`에 들어오면 먼저 앱 안 브라우저(사용자 에이전트: 카카오톡·네이버·인스타그램·페이스북·라인)나 PC(터치 없이 마우스가 주 입력)인지 보고, 맞으면 `/home?sheet=no-camera`로 보내 홈 위에 시트를 띄운다. 판별 기준은 `camera-place.test.ts`에 표로 있다
    - 「다른 브라우저로 열기」는 카카오톡(`kakaotalk://web/openExternal`, 공식 문서 없음)과 안드로이드(크롬 intent 주소)에서만 보인다. 아이폰의 다른 앱 안 브라우저는 웹에서 바깥 브라우저를 열 방법이 없어 숨긴다. **실기기 확인 필요**

    - 사진으로 읽으면 `/scan?gtin=…`, 「바코드 번호 입력」은 `/scan?manual=1`로 가서 카메라를 열지 않는 스캔 화면(`cameraOff`)에서 결과를 보인다
    - **개발 중 주의:** 데스크톱 브라우저로 `/scan`을 열면 PC로 판별돼 홈 시트로 간다. 스캐너 화면은 개발자 도구의 기기 모드(터치)로 본다
  - 3-1 읽힌 뒤 찾는 중(`scan-stage.tsx`의 `ScanFindingSheet`): 조회하는 동안 틀 아래 「바코드를 읽었어요」(카메라·사진일 때만, 직접 입력은 그대로) + 아래 버튼 줄을 숨기고 그 위에 흰 시트(제목 + 회색 틀 두 줄). 모달이 아니다. 짧은 진동은 스캐너가 읽은 순간 낸다(`lib/scan/use-scanner.ts`). 지금 목 조회는 바로 끝나서 거의 보이지 않고 실제 API를 붙이면 보인다
  - 3-1 사진에서 바코드를 못 읽었을 때(`scan-miss-sheet.tsx`의 `PhotoMissSheet`): 0-3x·3-1·카메라를 못 여는 곳에서 같은 시트. 못 읽은 이유(바코드 없음·사진 형식)는 나누지 않는다(디자인 메모). 카메라를 못 여는 곳에서는 시트 위에 시트를 띄우지 않고 안내 시트를 이 시트로 바꾸며, PC는 「바코드 번호 입력」을 숨긴다
  - 3-2 제품 결과(스캔 직후)(`scan-result-sheet.tsx`의 `ScanResultSheet`): 카메라 위에 붙는 결과 시트(모달 아님), 틀 아래 「다음 바코드를 비추면 결과가 바로 바뀌어요」. 시트는 화면용 모양 `ScanSheetProduct`를 받고, 지금은 목 조회 결과에 `src/components/scan/_fixtures.ts`로 브랜드·사진·점수·순위를 채운다. API 06단계에서 `lookupBarcode` 결과를 이 모양으로 바꾸는 mapper를 쓴다. 단 등급 없음(`INSUFFICIENT`)은 점수·등급이 없어 이 모양에 담기지 않으니 3-6 「아직 점수 없음」 등 따로 처리한다
    - 순위(「48개 중 12위」)는 실제 API에도 없어 값이 있을 때만 보인다(백엔드 확인 필요)
    - 등급 글자 A–E를 점수 구간 1–5로 그대로 대응시킨다(`scan-stage.tsx`의 `GRADE_BAND`)
    - 「비교함 담기」는 화면 안 상태로 「담김 ✓」만 바뀐다. 비교함 바는 「3-2 스캔 직후, 담았을 때」 작업에서 붙인다
    - 카메라가 읽고 있을 때는 디자인대로 시트를 화면 아래에 붙이고 아래 버튼 줄(사진·번호·이름)을 감춘다. 카메라가 안 읽는 단계(사진·번호로만 찾는 중, 다른 앱이 카메라를 쓰는 중)에서는 다른 제품을 더 찾을 수 있게 시트를 카메라 자리 안에 띄우고 버튼 줄을 남긴다(디자인에 없는 모양, UI 플랜 「남은 질문」 6)
    - 시트는 모달이 아니라서 제품 이름·점수는 화면 밖 상태 영역(`role="status"`)으로 알린다
  - 3-1에서 아직 임시인 것: 조회 실패·미등록 시트(예전 모양)는 3-6 등 해당 화면 작업 때 바꾼다. 카메라 점유 안내(「다른 앱이 카메라를 쓰고 있어요」 예전 띠)는 디자인에 v3 상태가 없어 그대로 두었다(UI 플랜 「남은 질문」 5)
  - 「나중에 할게요」는 `/search?from=camera-later`(2-3 검색에서 안내를 띄우는 표시. 06단계에서 이름을 맞춘다)
  - iOS처럼 허용을 오래 기억하지 않는 브라우저에서는 다시 방문할 때 0-3이 다시 뜰 수 있다. 권한 창이 다시 뜨는 상황이라 설명을 같이 보이도록 그대로 두기로 했다

`components/common/` 중 `cta-button`, `layer`, `card-tutorial`, `choice-card`와 `components/ui/`(shadcn)는 임시 화면용이다. 새 화면에서 쓰지 않는다.

### 화면 작업 순서 (화면 하나마다)

1. 기본 프레임 + 상태 프레임 전부 + 메모 + ⑩ 상태표 줄을 읽는다
2. 화면 props 타입을 **화면이 쓰는 모양으로** 정한다(서버 필드 이름 아님). API 타입은 만들지 않는다
3. 공통 부품을 먼저 쓰고, 없으면 공통 부품으로 추가할지 화면 전용으로 둘지 정한다
4. 상태 프레임을 모두 재현한다. 서버가 필요한 값은 `src/app/<경로>/_fixtures.ts`에 둔다(`src/lib/`에 두지 않는다)
5. 메모의 「누르면」 이동을 연결한다. 없는 화면은 경로만 건다
6. 검증 명령 통과 → 피그마 스크린샷과 비교
